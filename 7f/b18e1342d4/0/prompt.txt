  ## Decisions I made where the brief was silent
  1. **Learning waits for the supply history.** The registry sets up consumption before supply, and the replay runs in the background. Without the gate, the first learn would classify from hourly means the hours the log is about to cover, and folded days are never revisited. This is a wait for the primary source, not a fallback.
  2. **`_fold_day` no longer zero-fills device hours.** The old `.get(hour, 0.0)` would have undone the missing-child fix inside the learner. It is also what lets the apartment learn in mixed hours, as the plan's design 5 requires. One consequence: a device with no statistics at all now has no samples rather than zeros. `device_value` treats both as 0 kWh.
  3. **Fingerprint is always extended**, even when nothing is configured. Every installation therefore relearns once after upgrading, from the last `learn_days` (21) of recorder data, which also applies the two data fixes to old days. Anything in the profile older than that window is lost, as with any topology change. If you would rather not relearn unconfigured installs, only append the two entries when `active`.
  4. **Agreeing log meets carried states.** The log alone says `unknown` for hours in `[covered_from, first.at]`. I fill them with the agreeing carried state, which is how I read "where those hourly states meet the log".
  5. **Statistics are read up to `covered_from`, not just to the window end**, so a window ending before the log still sees a disagreeing first transition. Hours before the first decided hour inside the window are `unknown`; there is no lead-in before the window start. So a learning window's first day can lose a few night hours and miss the 20-of-24 rule.
  6. **The apartment must hang directly under the main meter**, otherwise `exclusive_series` raises `ValueError`. With a nested apartment, which intermediate meters still contain it on meter 2 cannot be known. The live installation fits this.
  7. **Running partial hour in `get_series` also goes through the tree.** It used `max(0, cur_main − Σ raw partials)`, which double-counted nested sub-meters, clamped, and ignored the supply. The running hour's device bars are now exclusive values, like the past hours'. This is a small visible change outside the two named callers, made because it is the same calculation.
  8. **The dropped-hour log covers the whole learning window**, so the message says so, rather than "in this run".
